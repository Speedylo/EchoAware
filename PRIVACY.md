# EchoAware Privacy Policy

_Last updated: 2026-05-12_

EchoAware is a Chrome extension that detects YouTube echo chambers and suggests alternative search queries. This policy describes exactly what data the extension handles, where it goes, and why.

We designed EchoAware around the principle that **your viewing history is yours** — it stays in your browser and is never sent to any server. The only data that ever leaves your device is a short list of YouTube titles, sent only when an echo chamber is detected.

---

## 1. Data we collect on your device (never sent)

The following data is stored entirely inside your Chrome profile (`chrome.storage.local` and IndexedDB). We have no access to it.

| Data | Why | Where | Retention |
|---|---|---|---|
| Video URLs you visited on `*.youtube.com` | Deduplication ("have I seen this?") | IndexedDB | Cleared on uninstall |
| Video titles | Embedded locally to compute topic clusters | IndexedDB | Cleared on uninstall |
| 384-dimension embedding vectors | The ML clustering input | IndexedDB | Cleared on uninstall |
| Session diversity score, cluster assignments | Drives the popup display | IndexedDB | Cleared on uninstall |
| Install token (a random UUID) | Per-install rate limiting on the inference service | `chrome.storage.local` | Cleared on uninstall |

These records are never transmitted off your device. We do not have a backend that can read them.

---

## 2. Data we send off-device (only on alert)

When the diversity score crosses the alert threshold **and** the dominant cluster has not already been analysed in this session, EchoAware sends **one HTTPS request** to our Cloudflare Worker at:

```
https://echoaware-api.<account>.workers.dev/v1/escape-queries
```

The request contains:

- **Up to 5 YouTube video titles** from the dominant cluster (each truncated to 120 characters)
- **Your install token** as the `X-Install-Token` header (a random UUID generated on first run — see §4)
- **The extension version** as the `X-Client-Version` header

The request contains nothing else. No video URLs, no full history, no channel data, no Google account information, no IP-derived identifiers from us.

The Worker forwards the titles to **Cloudflare Workers AI** (running the `@cf/meta/llama-3.1-8b-instruct` model) to generate a topic label and 3 search query suggestions. The response is returned to your browser; nothing is persisted.

This request fires at most a handful of times per day on a normal usage pattern — only when a new echo chamber forms.

---

## 3. Sub-processors

**Cloudflare, Inc.** acts as a sub-processor for the inference request described in §2. Cloudflare's privacy practices apply to:
- Workers infrastructure (the Worker that receives titles)
- Workers AI (the model that processes them)
- Edge metadata (IP address visible at the Cloudflare edge — see §5)

Cloudflare's Privacy Policy: https://www.cloudflare.com/privacypolicy/

We do not use any other third-party services.

---

## 4. The install token

The install token is a random UUID (e.g. `84c917a3-6b8f-4964-8443-33118fc8b2d1`) generated by your browser the first time the extension runs. It is sent with each inference request to enforce a per-install rate limit (currently 10 requests per 24 hours).

The token is:

- **Stored locally** in `chrome.storage.local` on your device.
- **Hashed server-side** (SHA-256) before being used as a rate-limit key. The raw token is never written to any server-side store.
- **Not linked to any account, email, or IP** by us. It is not a tracker — its only purpose is to prevent a single install from exhausting the shared inference budget.
- **Resettable** by uninstalling and reinstalling the extension. The token is regenerated on next run.

---

## 5. What Cloudflare can see at the edge

Standard HTTPS request metadata reaches Cloudflare regardless of the request body:

- The **IP address** you are connecting from (used by Cloudflare for routing and abuse mitigation)
- HTTPS request headers (`User-Agent`, etc.)

Cloudflare may retain this metadata according to their own retention policies. We do not log or store it ourselves, and we do not correlate it with the install token or video titles.

---

## 6. What we do NOT do

- We do **not** sell your data.
- We do **not** track your browsing outside of `*.youtube.com`.
- We do **not** persist video titles, URLs, or watch history in any server-side log, database, or analytics system.
- We do **not** use cookies, analytics, telemetry, or fingerprinting in the extension.
- We do **not** show ads.
- We do **not** share data with advertisers, brokers, or third parties beyond the Cloudflare sub-processor described in §3.

---

## 7. Workers AI no-log policy

The Cloudflare Worker that handles inference is built to log only aggregate counter values (request counts per day, error rates) — never the contents of requests. Specifically:

- No `console.*` statements in the Worker source reference titles or tokens (enforced by a unit test).
- The Worker does not write titles to any KV namespace or external store.
- Cloudflare Workers Observability (where enabled on staging) captures request metadata only — never request or response bodies. Titles are in the POST body and are therefore not captured.

---

## 8. Data subject rights

You can:

- **Stop all data flow** at any time by disabling or uninstalling the extension.
- **Delete all locally-stored data** by uninstalling the extension (Chrome wipes the extension's storage automatically).
- **Reset your install token** by uninstalling and reinstalling.
- **Inspect what is sent** at any time using Chrome DevTools → Network tab while the extension is enabled.

If you are a resident of the EU/UK, you have rights under the GDPR including access, rectification, erasure, and objection. Since we do not retain any data that could identify you, most of these rights are satisfied by uninstalling the extension. For any other request, contact us (§10).

---

## 9. Children

EchoAware is not directed at children under 13. We do not knowingly collect any data from anyone, including children.
